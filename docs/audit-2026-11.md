## B. Betrieb & Deploy

| # | Prio | Befund | Ort |
|---|---|---|---|
| B1 | mittel | **`deploy.sh` baut im laufenden Verzeichnis.** `next build` überschreibt `.next/` während die alte Instanz noch läuft → Nutzer bekommen in der Build-Phase 404 auf Chunks / kaputte Seiten; scheitert der Build, ist `.next` halb kaputt und ein späterer Neustart startet nichts Lauffähiges. Abhilfe: in separates `distDir` bauen und umschalten, oder zumindest Build-Fehler vor jedem Restart abfangen (passiert durch `set -e` bereits — aber die laufende Instanz liest schon das halbe `.next`). | `deploy.sh` |
| B2 | mittel | `npm install` statt `npm ci` im Deploy → kann `package-lock.json` auf dem Server verändern; der nächste `git pull` scheitert dann am lokalen Diff. | `deploy.sh:24` |
| B3 | ~~mittel~~ erledigt | **Node-Version war nirgends festgelegt.** Lokal läuft per nvm Node 22.18, das `better-sqlite3`-Binary war aber am 21.08. von einer anderen Laufzeit (ABI 147 ≈ Node 25, vermutlich IDE/Agent-Tool mit eigenem Node) gebaut → 14 Testdateien rot. *Behoben 12.11.2026:* `npm rebuild better-sqlite3` (210/210 grün), `.nvmrc` (22.18.0) und `engines: >=22 <23` ergänzt. Server nutzt Node 22 über `deploy.sh`. | `package.json`, `.nvmrc` |
| B4 | ~~niedrig~~ *erledigt 12.11.2026* | `NODE_BIN_DIR` lässt sich entgegen dem Kommentar **nicht** per Env überschreiben: Zeile 1 setzt den Wert hart, Zeile 2 (`${NODE_BIN_DIR:-}`) ist dadurch wirkungslos. Gleicher Fehler in `cron.sh`. Richtig: `NODE_BIN_DIR="${NODE_BIN_DIR:-/usr/local/node22/bin}"`. | `deploy.sh:11-12`, `scripts/cron.sh:28-29` |
| B5 | niedrig | Cron-Dispatcher holt verpasste Aufgaben nicht nach: Dauert das Backup (03:30) > 30 min, hält es die Sperre und `purge` um 04:00 fällt für diesen Tag stillschweigend aus. Gleiches bei Server-Reboot zur Unzeit. | `scripts/cron.sh` |
| B6 | niedrig | Abgeschlossener Worktree `.claude/worktrees/youthful-banach-6349bc` (Branch ist in `main` gemergt) liegt noch herum → `git worktree remove`. | |
