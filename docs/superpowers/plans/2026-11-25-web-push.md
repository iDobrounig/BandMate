# Web Push Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Web Push als zweiter Benachrichtigungskanal neben Mail: Sofort-Nachrichten und Termin-Erinnerungen, Kanalwahl pro Person (Push / Mail / beides), Rückfall auf Mail.

**Architecture:** `web-push` (VAPID, aes128gcm) auf dem Server, ein schlanker Service Worker `public/sw.js` ohne `fetch`-Handler. Abos liegen pro Gerät in `push_subscriptions`. Reine Kanal-Logik in `lib/notify-channels.ts`, der Versand in `lib/push.ts`. `notifyBand()` zieht nach `lib/notify.ts` und verteilt auf beide Kanäle, die Erinnerungen loggen je Kanal.

**Tech Stack:** Next.js 16 App Router, Drizzle + better-sqlite3, Vitest, `web-push@3.6.7` + `@types/web-push@3.6.4`.

**Spec:** [docs/specs/2026-11-25-web-push-design.md](../../specs/2026-11-25-web-push-design.md)

## Global Constraints

- UI-Texte Deutsch, Du-Form, knapp. Styling nur über vorhandene Klassen (`.card .btn .btn-primary .btn-sm .input .label .badge .headline`).
- `web-push` **exakt `3.6.7`** pinnen (nicht `4.0.0`: Major vom 06.11.2026, ESM-only, noch keine drei Wochen alt). `@types/web-push@3.6.4` als devDependency.
- Push ist **aus**, wenn `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` oder `VAPID_SUBJECT` fehlt: keine UI, kein Versand, kein Fehler. Env **zur Aufrufzeit** lesen, nicht beim Modul-Import.
- Öffentlicher Schlüssel geht als Prop vom Server an Client-Komponenten, **kein** `NEXT_PUBLIC_*`.
- Service Worker: **nur** `push` und `notificationclick`, **kein** `fetch`-Handler, kein Caching.
- Berechtigungsabfrage nur nach Tippen, nie automatisch.
- Push-Titel: `BandMate · <Bandname>`. Text ≤ 180 Zeichen. TTL 24 h (`86400`) Sofort, 12 h (`43200`) Erinnerungen. `urgency` `"high"` für Erinnerungen, sonst `"normal"`.
- Endpoint-Allowlist (Host exakt oder Subdomain): `fcm.googleapis.com`, `updates.push.services.mozilla.com`, `push.apple.com`, `notify.windows.com`. Nur `https:`. Endpoint ≤ 1000 Zeichen.
- Max. 10 Abos pro Person (ältestes fliegt). Test-Push max. 5 pro Minute pro Person.
- Kanalwahl-Werte exakt: `"beides" | "push" | "mail"`, Standard `"beides"`.
- Der Wochen-Digest bleibt reine Mail, **unverändert**.
- Bestandsverhalten für Personen ohne Gerät bleibt exakt gleich. Alle bestehenden Tests bleiben grün, ohne sie inhaltlich aufzuweichen.
- `data/` **nie** löschen oder überschreiben. Vor der Migration `./scripts/backup.sh --label pre-web-push`.
- Commits nur auf Zuruf von Ingo (deutsch, ein Feature-Block pro Commit). Der Plan markiert Checkpoints statt Commits.

## Review Focus

1. **„Nur Push“ und alle Geräte abgelaufen (410)** → Person bekommt diese Nachricht per Mail, nicht nichts. (Test in Task 5 und Task 6.)
2. **Doppelter Cron-Lauf, nachdem Push ok und Mail fehlgeschlagen ist** → zweiter Lauf schickt nichts (eine Erinnerung gilt mit einem `ok` als zugestellt). (Test in Task 6.)
3. **Gerät wechselt den Besitzer** (Anna meldet sich ab, Bert meldet sich am selben Browser an und aktiviert Push) → Abo gehört danach nur Bert, Anna bekommt dort nichts mehr. (Test in Task 3.)
4. **Push-URL mit fremder Herkunft oder `//evil.example`** → Klick öffnet `/`. (Test in Task 2; der Service Worker prüft zusätzlich.)
5. **Server ohne VAPID-Schlüssel, aber mit Abos in der DB** (z.B. Schlüssel entfernt) → kein Versand-Versuch, Personen mit „nur Push“ bekommen Mail. (Test in Task 5.)

```js
self.addEventListener("push", (event) => {
  let d = {};
  try { d = event.data ? event.data.json() : {}; } catch {}
  event.waitUntil(self.registration.showNotification(d.title || "BandMate", {
    body: d.body || "", icon: "/icon-192.png", tag: d.tag, data: { url: d.url || "/" },
  }));

self.addEventListener("notificationclick", (event) => {
  event.notification.close();
  const raw = event.notification.data && event.notification.data.url;
  const target = new URL(typeof raw === "string" ? raw : "/", self.location.origin);
  const url = target.origin === self.location.origin ? target.href : self.location.origin + "/";
  event.waitUntil((async () => {
    const wins = await clients.matchAll({ type: "window", includeUncontrolled: true });
    for (const w of wins) if (w.url.startsWith(self.location.origin)) { await w.focus(); return w.navigate(url); }
    return clients.openWindow(url);
  })());
});
```
